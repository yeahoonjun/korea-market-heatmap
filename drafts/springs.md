# 스프링 모션 — 시안

> **상태: 시안 (승인 전).** 사용자 요청 2026-11-15 "designbookmark.com/motion 같은 스프링 모션". 승인된 컨트롤 규칙은 [`docs/standards/controls.md`](../docs/standards/controls.md)(180 · 320 · 560ms, `--c-out` · `--c-in` · `--c-inout` · `--c-pop`)이고, 이 문서는 그걸 스프링으로 바꾸면 어떻게 되는지 재 본 것이에요. `src/`는 건드리지 않았어요.
> 만든 곳: `node scripts/springs.mjs` → `drafts/springs.css` · `drafts/springs.json` · 이 문서 · `drafts/springs.html`의 토큰 칸. 점검: `node qa/motion/test_springs.mjs`. 프레임: `drafts/springs.html?frames=1` → `qa/shots/springs/`.

## 1. 재는 법

- 질량 1, 0에서 멈춘 채 출발해 1로 가는 스프링(m·x″ + c·x′ + k·(x − 1) = 0)의 **닫힌 해**로 계산해요: ζ = c / (2√(k·m)), ω₀ = √(k/m). ζ < 1이면 덜 감쇠(넘쳐요), 1이면 임계, 1보다 크면 과감쇠(넘치지 않아요).
- **넘침** = 최댓값 − 1 (덜 감쇠면 100·e^(−ζπ/√(1−ζ²))와 같아요). **안정 시간** = |x − 1|이 0.5% · 0.1% 띠 밖에 마지막으로 있던 시각.
- **CSS 곡선**: `linear()`(Chrome 113 · Safari 17.2 · Firefox 112부터). 길이 `--sp-*-dur` = 0.1% 안정 시간(끝에서 맞춰지는 양이 1000px 이동에도 1px 미만). 점은 앞에서부터 현이 곡선을 덮는 한 가장 멀리 잡거나(위치 % 붙음) 고른 칸으로 잡고, 둘 중 **짧은 글자**를 골라요. 참 곡선과의 최대 오차는 모두 0.5% 미만(아래 표의 '오차').
- **판정**: 넘침이 **2% 넘으면 ⚠** — 사용자 규칙("넘침은 아주 조금만, 통통 튀는 곡선 없음"). 고친 쌍은 **같은 강성(같은 빠르기 ω₀)에 감쇠만 올려 ζ ≥ 0.8**(넘침 ≈ 1.5%)로 — 처음 움직임의 빠르기는 그대로고, 대개 더 빨리 멈춰요.

## 4. 움직임 줄이기 · 한계

- `html[data-motion="reduced"]`면 모든 `--sp-*-dur`가 0ms — controls.md §3과 같이 끝 상태로 바로예요(사용자 규칙 "임계 감쇠 또는 없음" 중 **없음**). 끌기를 놓은 스위치 손잡이처럼 꼭 움직여야 하는 곳은 같은 ω₀의 **임계 감쇠**(`springs.json`의 `critical`: c = 2√k, 넘침 0)를 JS로 쓰면 돼요.
- CSS 전환은 **속도를 이어받지 못해요**: 움직이는 중에 다시 누르면 새 전환이 속도 0에서 시작해서 살짝 멈칫해요(지금 cubic-bezier도 같아요). 끌기 · 빠른 연타가 중요한 곳(스위치 끌기, 티커)은 `springs.mjs`의 `spring(k, c, m, v0)` 닫힌 해를 rAF로 돌리면 이어져요(v0 = 지금 속도 ÷ 남은 거리).
- 스프링 토큰은 지금 길이(180 · 320ms)보다 **길어요**(제안 `--sp-*-dur` 290~632ms). 눈에 보이는 움직임은 0.5% 시간(235~510ms)쯤 끝나고, 그 뒤는 1px 안쪽 꼬리예요 — `transitionend`를 기다리는 코드는 그만큼 늦어져요.
- `left/right · width/height`는 레이아웃 속성이에요. 시안은 작은 컨트롤 하나라 괜찮지만, 구현 때는 controls.md §10처럼 표시 상자 하나에만 쓰거나 `clip-path`/`transform`으로 바꿔요.
