> 앞 문서 `docs/research/design-references.md`(글만 읽은 1차 조사)를 **보충**해요. 1차에서 못 본 것: designbookmark 컴포넌트가 실제로 움직이는 모습과 컴포넌트별 소스, bestdesignsonx 화면, X 글.

## 0. 한눈에 — 새로 알게 된 것

1. **designbookmark 82개 전부의 실제 소스와 재생 규칙을 확보**했어요. 갤러리 = 자체 51개(New 6 + 45) + Kokonut UI 24 + SmoothUI 7. 각 카드의 `play`(loop · tap · drag · hold · type · key, 간격 ms, 누를 대상)는 번들의 목록에 있고, 자체 컴포넌트는 Shadow DOM 안에서 **카드마다 따로 도는 엔진**(motion.js와 같은 코드, rAF 하나씩)으로 돌아가요.
2. **공용 토큰을 실제로 읽는 컴포넌트는 51개 중 13개**뿐이에요. 나머지 38개는 숫자를 직접 써요 — 갤러리 전체에 서로 다른 `k c` 쌍이 **100개**. 그리고 `tokens.css`의 6묶음(Morph select · Trends · Side nav · Rolling counter · Wheel picker · Magnetic tiles)은 **갤러리에 없는 컴포넌트**의 값이에요(`/motion-src/<그 이름>/` 모두 404). 공용 `--spring-follow` · `--stagger`도 쓰는 곳이 없어요.
   → design.md §6-2의 `open`(Morph select open) · `hl`(Morph select hl) · `roll` · `roll-w`(Rolling counter)는 **눈으로 확인할 수 있는 움직임이 없는 토큰**에서 강성을 가져온 셈이에요(값 자체는 문제 없음 — §7 P1).
3. **앞 · 뒤 가장자리(lead/trail)는 실제로 7곳**에서 써요: Tab pill `620/40 · 170/19`, Plan switch · Morph tooltip `620/36 · 190/19`, Spring dropdown 하이라이트 `620/36 · 200/20`(세로), Read along `520/40 · 210/26`, Pagination dots `520/34 · 140/18`, Rubber dock `640/38 · 150/16`. 강성비 3~3.7 : 1이 맞아요. **design.md의 `lead 620/40`은 Tab pill의 실제 값과 똑같아요.**
4. 반대로 이름이 **"Segmented control"인 컴포넌트는 lead/trail이 아니에요** — 위치 스프링 하나(`300/20`, ζ .58, 넘침 11 %)에 **속도로 찌그러짐**(폭 최대 +22 %, 높이 −11 %). Sidebar collapse도 표시는 스프링 하나(`380/28`). 1차 문서가 "Sidebar collapse(lead/trail)"라고 짐작한 건 틀렸어요.

## 2. designbookmark.com/motion

### 2-1. 갤러리가 어떻게 돌아가나

- 카드 = 400px 무대(`.motion-stage`) + 이름 · 만든 곳 + `Claude` · `Codex` · `Copy code` 세 버튼. 분류 칩 `All · Buttons · Inputs · Navigation · Cards · AI · Text · Saved`. 카드마다 무대 위에 밝음/어두움 단추.
- 자체 컴포넌트: `own-demo` 요소가 화면에 들어올 때 붙고 Shadow DOM에 `tokens.css + base.css + 컴포넌트 CSS`와 HTML을 넣은 뒤 **그 카드만의 스프링 루프**를 돌려요(motion.js와 같은 코드, `setSlow`로 ×0.25 가능 — 갤러리에 그 단추는 없어요). Kokonut/SmoothUI는 React 컴포넌트를 그대로 그려요(`motion` 라이브러리).
- **재생 규칙(`play`)**: `loop` = 컴포넌트 스스로 시연(대부분 "사람이 만지면 7~8초 멈춤"), `tap` = 정해진 간격마다 지정한 단추를 가짜 포인터로 누름, `drag` = 경로를 6px 간격 점으로 끌기, `hold` = 누르고 ms만큼 기다림, `type` = 글자 입력, `key` = 키 누름. 포인터가 카드 위에 있으면 재생하지 않고, 기기가 "동작 줄이기"면 아예 재생하지 않아요.
- "Copy code"는 `/motion-src/code/<id>.txt` — 자체 컴포넌트는 **공용 파일까지 다 들어간 HTML 한 파일**, 외부는 tsx 묶음. 폴더 `/motion-src/<이름>/index.html` + `*.css` + `*.js`도 따로 있어요.
- 프롬프트(번들 안 템플릿): 자체 컴포넌트는 "공용 스프링을 그대로(`tokens.css`의 같은 강성 · 감쇠)" 다시 만들라고 하고, 외부는 `npx shadcn add`로 설치하라고 해요.
- **라이선스**: Kokonut UI · SmoothUI 파일 머리에 MIT, React `command-button.tsx`도 MIT. **자체 HTML 컴포넌트 51개에는 라이선스 문구가 없어요**(파일 머리는 이름 · 출처 주소뿐) → 판세는 코드를 옮기지 않고 패턴과 수치만 참고해 `KH.spring`으로 새로 만들어요(1차 결정과 같음).

### 2-2. 엔진 · 토큰이 실제로 쓰이는 모습

- 엔진(1차 §1-2와 같음): 반암시적 오일러, dt ≤ 1/30초를 4번 나눠, 정지 판정 없이 rAF가 계속 돌아요. **갤러리에서는 카드마다 rAF가 하나씩** 돌아서, 화면에 카드가 여럿이면 rAF도 여럿이에요(판세의 "공용 rAF 하나 · 다 서면 끔"이 맞는 이유).
- 토큰을 읽는 컴포넌트 13개: Plan switch(공용 `lead · trail · pop · fade · soft`) · Letter limit(`pop · settle`) · Rubber dock · Goo menu · Morph island · Hold button · Jelly slider · Swipe deck · Springy input · Pull to refresh · Glass lens · Parallax ticket — 각자 자기 묶음.
- 쓰이지 않는 토큰: `--spring-follow` `--stagger`(45는 코드에 `.045`로 직접), Magnetic tiles · Morph select · Wheel picker · Trends · Side nav · Rolling counter 묶음 전부.
- 갤러리 안 `k c` 쌍 100개의 분포(넘침 기준): ζ < 0.5(넘침 16 % 넘음) 27개 — 거의 다 튐 · 끈적이 · 줄 · 고무 · 흔들기, ζ 0.5~0.75 46개, ζ 0.75~0.9 19개, ζ ≥ 0.9 8개. 가장 많이 쓴 쌍: `300/26`(ζ .75, 13곳) · `260/24`(.74, 7곳) · `300/22`(.64, 6곳) · `260/22`(.68, 6곳) · `300/24`(.69, 6곳).

### 2-5. 다시 보이는 패턴 (판세 관점)

1. **두 가장자리 표시** — 앞 강성 520~640, 뒤 140~210, 감쇠는 컴포넌트마다 다름(ζ .65~.90). 표시 폭은 최소값으로 자름(Plan switch 36px, Read along 16px), 방향은 목표가 오른쪽(아래)이면 오른쪽(아래) 가장자리가 앞.
2. **처음엔 그 자리에, 이어질 때만 이동** — Morph tooltip("나타날 곳에서"), glisse 메뉴 하이라이트, Read along(줄바꿈 · 첫 단어), Spring dropdown(메뉴 열 때 하이라이트는 고른 줄에 바로).
3. **나감은 짧고 먼저, 들어옴은 조금 늦게 · 길게** — Segmented(0.14초 뒤 교체), Morph island(140ms / 90ms 지연 + 350ms), Kokonut morph popover(나감 0.1초). 흐림은 3~6px.
4. **방향이 있는 교체** — 숫자는 커지면 아래에서(Stepper), 라벨은 표시가 간 방향으로(Morph tooltip), 값은 위로 굴러 올라감(Dropdown · Copy · Plan 청구 줄).
5. **속도를 모양으로** — 세그먼트 찌그러짐(속도 ÷ 1400, 최대 .22), 슬라이더 말풍선 기울기, 파일 칩 기울기, 커서 늘어남. 판세에서는 스위치 손잡이 늘어남만(design.md §7) 쓰고 나머지는 데이터 화면에 과해요.
6. **놓을 때 속도 이어받기 + 문턱 두 개(거리 또는 속도)** — 110px/0.11px/ms(Deck · Notification), 35 %/500px/s(Stack panel), 90 %/45 %+900px/s(Slide to confirm).
7. **두 벌로 정확한 색 뒤집기** — 알약 안 아이콘 한 벌(Rubber dock), 채움 아래 라벨(Hold button), glisse 라벨 줄 복제. 색 전환 시간 없이 "걸친 만큼" 바뀜.
8. **폭 · 높이 다른 스프링** — Morph island · Dynamic menu · Rubber dock 카드 · Command palette: 폭이 먼저, 높이가 늦게(줄어들 땐 반대로 높이를 빨리).
9. **자동 재생과 사람의 손을 구분** — 모든 loop가 사람이 만지면 6~8초 멈춤, Copy는 진짜 클릭만 클립보드, 갤러리는 포인터가 카드 위면 재생 중단.
10. **글꼴이 늦게 와도 맞게** — Word roll · Morph tooltip이 `document.fonts.ready`에서 폭을 다시 잼.

## 7. `docs/standards/design.md`와 다른 점 — 제안 (결정은 사용자)

각 항목: **[무엇이 다른가]** → 제안. "부딪힘" = 레퍼런스가 design.md와 반대, "빠짐" = design.md에 없음, "더할 것" = 있으면 좋은 것.

**P0. 근거 문장 바로잡기 (빠짐 · 사실 확인)**
- design.md 머리 · 1차 문서 §1-1 · §1-8은 모션 브리프를 X 글과 이어서 말해요. X 글은 영상 도구 18개 목록이라 **브리프의 출처는 "사용자가 붙여 준 글, 출처 미상"**으로 고치길 제안해요. 규칙 자체는 그대로.
- design.md §6-1 "빠르기(강성)는 레퍼런스(designbookmark) 그대로" → 실제로는 `open` · `hl` · `roll` · `roll-w`가 **갤러리에 없는 컴포넌트의 토큰**에서 왔어요. 값은 바꿀 필요 없고, 근거를 "판세가 정한 값(레퍼런스 강성 범위 안)"으로 적는 걸 제안해요. 눈으로 확인된 짝: `lead 620/40` = Tab pill 앞 가장자리 그대로, `trail 190/23` ≈ Tab pill · Plan switch 뒤(170~190), `follow 900/50` = Jelly slider · Swipe deck · Pull to refresh가 끄는 동안 쓰는 값, `island-w/h` 강성 = Morph island(토큰 · 실제 사용 모두).

**P1. `hl`을 두 가장자리로 (부딪힘 아님 · 더할 것)**

**P2. 세그먼트 "찌그러짐"은 넣지 않기 (부딪힘 — 확인용)**

**P6. 툴팁 · 하이라이트의 "처음 · 이어짐 · 떠남" (빠짐)**
- 레퍼런스: 처음 나타날 땐 **그 자리에서**(이동 없음) · 이미 보이는 중이면 새 자리로 이동 · 떠나면 **140ms 뒤** 숨김(Morph tooltip), 아이콘 툴팁은 **400ms 머문 뒤** 열리고 하나가 닫힌 뒤 **300ms 동안은 다음 것이 바로**(Toolbar), 메뉴 하이라이트는 처음 켜지는 줄에 전환 없이(glisse).
- design.md §7 툴팁은 "`follow`로 따라오고, 열림은 `fade`만"뿐이에요. 제안: 지도 타일 툴팁(따라가는 것)은 지금대로 + "처음엔 그 자리 · 숨김 지연 120~140ms(지금 120ms 규칙 유지)", **아이콘 키 툴팁(데스크톱 마우스만)**은 400ms 지연 + 300ms warm. 휴대폰엔 hover 툴팁 없음(§8과 같음).

**P7. 끌기 세부 숫자 (더할 것)**
- design.md §8에 있는 것: 머묾 150ms · 끌기 시작 6px(스위치 4px) · 던짐 0.11px/ms. 레퍼런스에서 더할 만한 것: **놓는 속도는 마지막 80~100ms 표본으로만**(Smooth tab · Notification · Wheel), **축 잠금 6px**(가로/세로 결정 전 6px 여유), **문턱은 거리 또는 속도 둘 중 하나**(시트: 높이의 35 % 또는 던짐 — Stack panel · Notification), 끝 너머는 끈 거리의 일부만(고무줄 0.55, design-references R10과 같음), 아래 막대 2쪽 넘기기는 **옆 쪽을 투명도 .35로 미리 보이게**(Smooth tab). 키를 누르고 있을 때 바로 이동은 이미 §8에 있어요(Smooth tab이 같은 규칙 — 확인).

**P8. 시트 · 펼침의 높이 (부딪힘 — 판세 문서끼리)**
- AGENTS §3-34(시장 요약 카드)는 "자세히를 누르면 그 자리에서 **자라요**(`open`/`close`)"인데, controls.md는 "높이 애니메이션은 하지 않아요"예요. 레퍼런스는 높이를 스프링으로 움직여요(Plan switch 줄 열림, Spring dropdown, Dynamic menu, Expand card). 제안 두 길: ⓐ **카드 모양(배경 판)만 `open`으로 자라고** 아래 내용(뉴스 카드 등)은 한 번에 자리를 옮김 + 안 내용은 §6-4로 나타남(레이아웃 흔들림 1번) ⓑ 높이 자체를 스프링(아래가 미끄러지듯 밀림, 휴대폰에서 스크롤 위치가 움직임). **ⓐ 추천**(Emil "레이아웃 속성 애니메이션은 비쌈", 판세 "지도 위치 불변"). 길이는 크기 차이에 비례해 자르기(`clamp`) — Emil *choreograph*.

**P9. 글자 바꿈에 방향 (더할 것)**
- design.md §6-4는 "위로 4px 나감 → 아래에서 4px 들어옴" 한 방향이에요. 레퍼런스: 숫자는 **커지면 아래에서 · 작아지면 위에서**(Number stepper), 옆으로 옮긴 표시의 라벨은 **움직인 방향으로**(Morph tooltip). 제안: 탭 아래 등락률 · 종목 수처럼 크기가 있는 수는 방향을 따르고, 라벨은 지금처럼 위로. 흐림 2px · 4px 거리는 그대로(레퍼런스 3~6px보다 작지만 시세 화면엔 맞아요).

**P10. 숫자 굴림 세부 (더할 것)**
- design.md `roll` · `roll-w`는 강성 · 감쇠만 있어요. 레퍼런스에서: ① **바뀐 자리만** 굴림(Boarding pass · Dynamic text) ② **짧은 길로**(9 → 0은 앞으로 한 칸, Profile) ③ 자리 간격은 **오른쪽 자리부터**(받아올림처럼, Profile 60ms — Plan switch는 왼쪽부터 45ms라 레퍼런스끼리 다름, 1차 문서는 오른쪽부터 40ms 제안) ④ 드럼 위아래 **페이드 마스크 14 %**(Plan switch) ⑤ 굴리는 동안만 세로 흐림(Rolling counter 토큰 `count-blur 1`). 제안: ①②③(오른쪽부터 40ms)④를 §6-2 표 아래에 한 줄로. ⑤는 넣지 않음(흐림 비용 · 숫자 읽기).

**P11. 비동기 단추는 크기 고정 — 그대로 (부딪힘 — 확인용)**
- Loading to success · Plan switch 업그레이드 · Copy button은 단추가 원으로 줄거나 폭이 글자에 맞게 변해요. 판세 controls.md(사용자 결정 2026-11-13 "레이아웃 고정, 글자 상자 최장 폭")와 반대예요. **판세 그대로를 추천.** 다만 Copy button의 "아이콘 교차(복사 → 체크, −40° 돌며 .5) + 단어 굴림"은 크기를 바꾸지 않고도 쓸 수 있어요 → 시장 요약 카드 "글로 복사"(AGENTS §3-34 ②)에 그대로 맞아요.

**P12. 자동 재생 · 진짜 입력 구분 (빠짐)**
- Copy button: 자동 재생은 클립보드를 절대 건드리지 않고 `isTrusted` 클릭만. 판세에도 "보여 주기"가 생기면(예: 첫 방문 안내, 시안 데모) 같은 원칙 — 실제 부작용(복사 · 저장 · 알림 권한 · 외부 링크)은 사람의 입력에서만. design.md §9 글 또는 §8에 한 줄 제안.

**P13. 길게 누르기 진행 (더할 것, 선택)**
- 판세 시계 길게 누르기 500ms(세계 시각)는 지금 진행 표시가 없어요. Hold button: **누르는 동안은 선형 진행**(스프링 아님), 놓으면 온 만큼에 비례해 빠짐. 제안(선택): 시계 둘레 정규장 호와 겹치지 않는 얇은 테두리로 500ms 진행 — 또는 지금처럼 없음(500ms는 짧아서 없어도 됨).

**P14. 티커 · 지수 선 끝 "미리 하나" (더할 것)**
- Voice input: 오른쪽 화면 밖에 막대 하나를 미리 두어 새 값이 "툭" 생기지 않게. 판세 시장 띠(티커)와 지도 머리줄 지수 선(A/B)이 새 점 · 새 항목을 붙일 때 같은 문제가 있어요. 제안: 티커는 화면 밖에 다음 항목을 이미 배치, 지수 선은 새 점을 이전 끝점에서 `value`로 늘려 붙임.

**P15. 아이콘 세트 후보 (더할 것, 선택)**
- design.md §4 "아이콘 한 벌, 16px에 1.75"를 실제 세트로 정할 때: designbookmark 안내의 Lucide(ISC) · Tabler(MIT) · Phosphor(MIT)는 선 굵기를 조절할 수 있어요. 갤러리 자체는 24 그리드 · 선 1.8(motion.js `svg`) · Kokonut Undo는 1.5. 지금 손으로 그린 SVG를 유지해도 돼요 — 고를 일.

**P16. `will-change` · 그림자 · 색 — 그대로 (부딪힘 — 확인용)**
- 레퍼런스는 글자를 품고 크기가 바뀌는 단추에 `will-change: width, transform`(Plan switch), 그림자 0(`--sh:0`, "그림자 없음"), 완료 = 초록(Loading · OTP · Hold)을 써요. design.md §6-5 · §5 V1 입체 · §2(완료는 앰버)와 반대지만 **design.md 그대로를 추천**(사용자 결정 2026-11-13 · 11-15). Emil *animation-performance*도 "`will-change`는 흔들림을 본 뒤에만"이라 판세 쪽에 가까워요.

**P17. bestdesignsonx에서 (§4)**
- **a. 큰 숫자의 소수부 (더할 것, 선택)** — 머리에 크게 쓰는 수 중 소수가 있는 것(종목 · 지수 시트 머리의 지수 값, 지표 탭 시트의 환율 · 금리, 시장 요약 카드의 지수)에서 소수점 뒤를 한 단계 작은 글자(`--fs` 한 칸 아래) 또는 `--fg2`로. **표 · 목록 · 티커처럼 열을 맞추는 숫자에는 쓰지 않아요**(tabular 정렬이 깨져요). design.md §3(글자)에 "머리 숫자의 소수부" 한 줄.
- **b. 차트를 짚는 동안 머리 숫자 (빠짐)** — 지금 종목 차트는 십자선을 움직이면 범례 줄(시각 · 등락 · 시고저종 · 거래량)만 바뀌어요. 레퍼런스처럼 **짚는 동안 머리의 가격 · 등락 · 시각을 그 봉 값으로**, 놓으면 현재가로 돌아가는 방식을 제안해요. 짚는 동안은 손가락을 따라 **바로** 바꾸고(굴림 · 글자 바꿈 없음 — 너무 잦아요), 놓을 때만 `roll`로 바뀐 자리만 굴러 돌아와요. 실시간 갱신은 짚는 동안 머리에 쓰지 않고 놓은 뒤 반영. 막대 차트(재무 · 투자자 순매수)는 짚은 막대 말고는 `--fill` 수준으로 옅게. 다른 길: 지금처럼 범례 줄만(머리는 언제나 현재가 — 실시간과 헷갈릴 일이 없음). 판세는 "지금 값"이 핵심이라 **다른 길도 충분히 그럴듯해요** — 사용자 선택.
- **c. 기간 · 간격을 바꿀 때 막대가 다시 자라지 않음 (부딪힘 — 확인용)** — 레퍼런스는 바꿀 때마다 막대를 바닥에서 다시 키워요. design.md §6-1 · P4(데이터는 실제로 바뀐 것만)대로 **새 데이터는 `fade` 교차만**을 추천. 레퍼런스에서 가져올 것은 "부제 · 요약 수가 칩과 함께 바뀐다"(종목 차트의 기간 등락률 · 기준 문구가 간격 탭과 같은 순간에 §6-4로 바뀜)뿐.
- **d. 다시 보기 슬라이더에 눈금 + 이름 알약 (더할 것, 선택)** — 391칸(1분)짜리 슬라이더에서 시각 눈금(정각 · 30분)을 세로선으로, 손잡이 위에만 "13:05" 알약. 지금 모양을 바꿀 까닭이 생길 때 고를 일.
