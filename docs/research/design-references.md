# 디자인 레퍼런스 조사 — 판세 디자인 기준을 먼저 정하기

> 상태: **조사 · 제안**이에요(결정 아님). 2026-11-15. 승인된 규칙(`docs/standards/controls.md`, `docs/motion-brief.md`, `themes.md`)을 바꾸려면 사용자 결정이 필요해요 — 충돌하는 곳은 §2-4에 모아 뒀어요.
> 방법: GitHub 저장소 3개(glisse · taste-skill, 그리고 designbookmark /skills가 가리키는 Emil Kowalski · Jakub Krehel 스킬)는 `git clone`해서 소스 · 규칙 파일을 직접 읽었어요. 나머지 사이트는 WebFetch로만 읽었어요. 스프링 수치(ζ · 넘침 · 안정 시간)는 레퍼런스가 준 k · c로 제가 직접 계산했어요(질량 1, 반암시적 오일러 dt 0.25ms, 정지 상태에서 출발, **안정 = 남은 거리가 이동 거리의 0.5% 안에 머물기 시작한 시각**, **넘침 = 목표를 지나친 최대 거리 ÷ 이동 거리**).
> 표기: 스프링은 `k c`(강성 · 감쇠 계수, 질량 1) — designbookmark 토큰과 같은 순서. ζ(감쇠비) = c ÷ (2√k). ζ 1 = 넘침 없음, ζ 0.9 ≈ 0.1 %, ζ 0.8 ≈ 1.5 %, ζ 0.7 ≈ 4.6 %, ζ 0.5 ≈ 16 %.
> 같은 작업 트리의 `scripts/springs.mjs`(다른 에이전트, 커밋 전)가 designbookmark 스프링으로 토큰을 만들고 있어요(규칙 "넘침 ≤ 2%, 넘으면 같은 강성에 감쇠만 올려 ζ ≈ 0.8"). 이 문서의 이름(`lead`·`trail`·`follow`·`settle`·`fade`·`morph-open`·`morph-hl`·`island-w/h`·`roll`·`roll-w`)은 거기에 맞췄고, §2-2의 제안값은 그 규칙 안에 있어요.

## 0. 한눈에 (상위 규칙 제안)

1. **스프링 한 엔진, 토큰은 `k c` 문자열** — `:root`에 `--sp-<이름>: 620 45`처럼 두고 JS가 읽어요(designbookmark 방식). 엔진은 glisse처럼 **닫힌 해 + 공용 rAF 하나 + 멈추면 rAF도 멈춤**.
2. **감쇠비 3단**: 인터페이스 모양 · 위치 **ζ 0.9**(넘침 ≈ 0.1 %), **손가락이 놓고 간(속도가 있는) 것만 ζ 0.8**(≈ 1.5 %), **데이터(숫자 · 막대 · 타일 크기) ζ 1.0**(넘침 0). 레퍼런스의 ζ 0.35~0.7 값(넘침 5~31 %)은 강성만 가져와요.
3. **닫힘은 열림보다 짧고 넘침이 없어요**: 열림 `morph-open 360 35`(≈ 310ms), 닫힘 `close 900 57`(≈ 220ms, glisse 메뉴 닫힘값).
4. **모양 하나가 크기 · 모서리 · 색을 바꾸고, 안의 글자는 따로**: 나가는 글자 100ms(opacity → 0, blur 0 → 2px, −4px), 들어오는 글자 60ms 뒤 180ms(blur 2px → 0, +4px → 0). 모양이 25 % 갈 때까지 새 글자를 보이지 않아요(glisse 메뉴는 15 %부터).
5. **`will-change`는 글자를 품고 크기가 바뀌는 것에 절대 안 붙여요** — glisse가 바로 이걸 하고 있어서(라벨 줄을 품은 `.lg-tab-tint`에 `will-change: transform` + scale) 따라 하지 않아요. 옮기기만 하는 것(티커 띠, 글자 없는 표시 상자)에만, 움직이는 동안만.
6. **금지 목록(브리프 + 레퍼런스)**: 통통 튀는 곡선(ζ < 0.8, 베지어 y > 1 — 승인된 완료 체크 `--c-pop`은 §2-4 결정 대기), 파티클(“Like burst”), 빛 · 후광(glow), UI 크롬의 그라데이션 · 그레인, 섞인 아이콘 선 굵기, 기다리는 시간(dead time), 글자 섞기(scramble), 끈적이(goo), 자석 버튼, 기울이기 · 패럴랙스.
7. **글자 크기 7단**: 11 · 12 · 13 · 14 · 16 · 20 · 26px (지금 20가지 — 10.5 · 11.5 · 12.5 · 13.5 · 14.5 반 단계 없앰). 타일 라벨만 예외(타일에 맞춤).
8. **간격 8단** 2 · 4 · 6 · 8 · 12 · 16 · 24 · 32px(+ 1px 선), **모서리 6단** 2 · 4 · 8 · 12 · 16 · 999px, 겹친 면은 **안쪽 = 바깥 − 여백**.
9. **아이콘 한 벌 · 선 하나**: 16px에 1.75px(옆 글자 500~600), 14px에 1.5px, 끝 · 이음 둥글게, `currentColor`, 보통은 외곽선 · 켜짐은 채움. (지금 1 · 1.2 · 1.4 · 1.5 · 1.6 · 1.7 · 1.8 · 2 · 2.1 · 2.4가 섞여 있어요.)
10. **터치 규칙**(glisse · Emil): hover는 `(hover:hover) and (pointer:fine)` 안에서만, 가로 스크롤 안의 컨트롤은 **150ms 머문 뒤에야** 터치를 가져가요, 끌기는 6px(세그먼트) · 4px(스위치)부터, 손을 떼는 지점이 컨트롤 위아래 24px 안이면 누름으로 쳐요, 놓을 때 속도 > 0.11px/ms면 던진 것.

## 1. 레퍼런스별

### 1-1. 사용자가 붙여 준 모션 브리프

**무엇**: 짧은 모션 규칙 묶음(아래 X 글의 내용으로 보이지만 X 글을 읽지 못해 확인은 못 했어요, §1-8).

**규칙**(그대로 옮김 · 요약)
- 모양 하나가 크기 · 모서리 · 색을 바꾸며 변하고, 그동안 내용은 **짧은 blur**로 바뀌어요.
- 스프링을 어디서나, 넘침은 많아야 아주 조금.
- 금지: 통통 튀는 곡선, 파티클 터짐, 빛(glow), UI 크롬의 그라데이션, 선 굵기가 안 맞는 아이콘, 기다리는 시간, 템플릿 같은 것.
- 모양이 변하는 상자 안에서 바뀌는 글자는 **자기만의 나감/들어옴 시간**이 있어야 해요.
- 글자를 품고 크기가 바뀌는 것에 `will-change`를 두지 않아요(글자가 비트맵으로 굳어 흐려져요).

**판세 지금 문서와 겹치는 점**: `controls.md`의 "튀는 건 완료 체크뿐", 데이터 넘침 금지는 이미 같아요. 다른 점은 §2-4.

**motion.js** ("Tiny spring engine shared by every component.")
- API: `S(x,k=400,c=30)` 스프링 만들기, `tune(s,k,c)`, `step(s,dt)`, `token/num/spring(name)` — CSS 변수 `"k c"`를 숫자 두 개로 읽어요, `after(sec,fn)`(느린 재생에 맞춘 타이머), `register({frame,render})`, `svg(path, sw=1.8)` — **아이콘은 24×24, 선 1.8, 끝 · 이음 둥글게**로 통일.
- 적분: 반암시적 오일러 `a = −k(x−t) − c·v; v += a·dt; x += v·dt`. 프레임 dt를 **1/30초로 자르고 4번 나눠** 돌려요. 질량 없음(=1). **멈춤 기준 없음 — rAF가 계속 돌아요**(판세에는 그대로 쓰면 안 돼요: 배터리).
- 느린 재생 `setSlow(true)` → 시간 ×0.25(QA에 좋은 아이디어: 판세도 `?slow=4` 같은 디버그 배율).
- 움직임 줄이기: 처음 한 번만 읽고, `tune()`만 감쇠를 **임계 2√k로 바꿔요**(멈추지 않고 넘침만 없앰). `S()`로 만든 스프링은 적용 안 돼요(빈틈).

**무엇**: 에이전트 스킬 50개 목록(방향 · 리뷰 · 만들기 · 모션 · Figma · 모바일 · 그래픽). "두 개를 같이 쓰면 서로 당기니 하나만" 이라는 안내. 대시보드 · 데이터 시각화 전용 스킬은 없어요. 판세에 직접 맞는 건 Emil Kowalski(apple-design, animate, review-animations, gestures, mobile-native)와 Jakub Krehel(better-ui, better-typography, better-colors). 두 저장소 모두 **MIT**(2026). 아래는 규칙 파일에서 뽑은 값이에요.

**Emil Kowalski — apple-design / review-animations / mobile-native**
- 빈도로 정해요: 하루 100번+ (단축키 · 명령 팔레트) **애니메이션 없음**, 하루 수십 번(hover · 목록 이동) 줄이거나 없앰, 가끔(모달 · 시트 · 토스트) 보통, 드묾(첫 실행 · 축하) 즐거움 허용. "Never animate keyboard-initiated actions".
- 길이: 누름 100~160ms, 툴팁 · 작은 팝오버 125~200ms, 드롭다운 150~250ms, 모달 · 시트 200~500ms, UI는 300ms 아래. 곡선 `ease-out (.23,1,.32,1)`, 화면 안 이동 `(.77,0,.175,1)`, 시트 `(.32,.72,0,1)`. **ease-in은 UI에 금지**.

6. **스위치 누름**(`controls.md` §5-8 "크기 그대로"): taste-skill · designbookmark식 손잡이 늘어남(가는 쪽 3px, `follow` 앞 · `settle` 뒤 가장자리)은 브리프의 "모양 하나가 바뀜"에 맞지만 승인 규칙과 달라요.
7. **글자 바꿈**(`controls.md` §5-3: ±6px, blur 없음, 180 + 180ms): R3(±4px, blur 2px, 100 / 60 + 180ms)로 바꿀지.
8. **타일 누름 `scale(.985)`**(`motion-brief.md` (g))와 `controls.md` §8 "데이터 표시는 누를 때 가라앉거나 커지지 않아요"가 이미 서로 달라요 — 판세 문서 안의 불일치(이 조사와 별개로 정리 필요).
9. **표시 이동 방식**: 지금 left/right(절대 위치 상자) + 곡선 → 스프링 두 개(앞 · 뒤 가장자리)로. 겉보기는 같고, 연달아 누를 때 끊김이 없어져요.

## 3. 판세에 들일 상호작용 패턴 8가지

| # | 패턴 | 스프링 · 값 | 판세 어디에 |
|---|---|---|---|
| 1 | **앞 · 뒤 가장자리 표시**(세그먼트 · 탭 · 밑줄) — 가는 쪽 가장자리가 먼저, 뒤가 따라와 늘었다 줄며 도착. 고른 칸 글자색은 표시 안의 복제 라벨 줄을 잘라 보여 줘 **정확히 걸친 만큼** 바뀌게(glisse). 누른 칸을 6px 넘게 끌면 표시가 손가락을 따라가고 놓은 자리의 칸(트레이 끝에서 자름), 놓는 순간 고름 | 앞 `lead 620 45`, 뒤 `trail 190 25`; 끄는 동안 둘 다 `2500 94`(glisse drag), 놓으면 `settle 280 27`에 속도 넘김; 키보드 반복은 즉시 | 시장 탭, 크기 · 색 기준 · 종목 수 · 색 범위 세그먼트, 종목 페이지 차트 간격 · 시세 정보 탭, 공시 종류 밑줄, 해외 정렬 · 목록/지도 |
| 2 | **트리거에서 자라는 팝오버 · 셀렉트**(모양 하나) — 키의 사각형이 그대로 목록 카드로 커지고(폭 · 높이 · 모서리 12 → 12, 바탕 `--key-bg` → 팝오버 면), 키 글자는 0~45 %에 blur 0 → 6px로 사라지고, 목록 줄은 25 %부터 blur 2px → 0으로 들어와요. 줄은 `clip-path: inset(… round r)`로 모양 안에만 | 열림 `morph-open 360 35`, 닫힘 `close 900 57`(줄이 먼저 사라짐), 줄은 scale 없음(R4), 첫 줄 포커스 · Esc는 키로 | 색 기준 `오늘 ▾`(≥1280), 휴대폰 `통합 ▾` 메뉴 칩, 관심 그룹 `⋯`, ☆ 그룹 고르기(데스크톱), 시계 길게 누르기 세계 시각 |
| 3 | **하이라이트 판** — 열린 목록 안에서 마우스 · 끌기 · ↑↓로 판 하나가 줄 사이를 미끄러짐, **처음 켜지는 줄은 전환 없이 바로**, 구분선을 건너도 꺼지지 않음. 고른 줄은 앰버 글자 + 체크(지금 규칙) | `morph-hl 620 45`; 처음 줄 0ms; 휴대폰은 끌어서 고르기(누른 채 줄 위로 → 놓으면 고름) | 2번의 팝오버들, 검색 제안 목록, 티커 항목 고르기 분류 |
| 4 | **스위치 손잡이 늘어남 · 끌기** — 누르면 손잡이가 가는 쪽으로 3px 늘어나고(앞 · 뒤 가장자리를 다른 스프링으로), 켜기 · 끄기 때도 앞이 먼저 가서 늘었다 줄며 도착. 채움 색은 위치와 같은 진행값. 끌면 따라오고 끝 너머는 1/22만 | 앞 `follow 900 54`, 뒤 `settle 280 27`(끌어 놓을 때 속도 넘김), 끌기 4px부터, 머묾 150ms 전 세로 10px면 스크롤 | 표시 설정 · 화면 설정 스위치, 지분 공시 포함 (§2-4-6 결정 뒤) |
| 5 | **숫자 자리 굴림 + 폭** — 바뀐 자리만 위 · 아래로 굴러요(지금 규칙), 움직이는 동안만 세로 1px blur, 자리 수가 바뀌면 교차 대신 상자 폭이 스프링으로 늘고 새 자리가 들어옴. 오른쪽 자리부터 40ms 간격 | `roll 320 36`(ζ 1, 넘침 0), 폭 `roll-w 380 39`(ζ 1); 색은 바뀐 순간 새 색 | 시장 띠, 종목 페이지 현재가 · NXT 줄, 탭 아래 등락률, 지도 머리줄 종목 수 · 등락률, 다시 보기 시각 |
| 6 | **시트 = 누른 것에서 자람 + 끌어 닫기** — 타일 · 칩을 누르면 그 사각형이 시트 몸통으로 커지고(폭 · 높이 · 모서리 2 → 16), 내용은 25 %부터 들어옴. 휴대폰 바텀 시트는 손잡이 · 머리를 끌어 닫기: 1:1로 따라오고, 위로는 고무줄 0.55, 놓을 때 속도 > 0.11px/ms 아래면 닫힘, 아니면 투사점 기준 열림/닫힘 | 열림 `morph-open 360 35`(데스크톱) · 바텀 시트 `settle 280 27` + 속도, 닫힘 `close 900 57`, 배경막 opacity `fade 420 37` | 빠른 시트(타일 누름), 표시 설정 시트, 관심 그룹 바텀 시트, 해외 · 지표 상세 시트, 티커 항목 고르기 |
| 7 | **결과 섬**(Morph island + Loading to success) — 아이콘 키 아래 말풍선을 따로 띄우는 대신, 키 바로 아래에서 작은 알약이 **폭 · 높이를 다른 스프링으로** 펼쳐지며 "✓ 새 시세를 받았어요"가 되고, 머문 뒤 다시 접혀 사라져요. 키 자체 크기는 그대로(레이아웃 고정) | 폭 `island-w 380 36`, 높이 `island-h 300 32`, 글자는 R3, 머묾 `--c-dwell` 1120ms, 접힘 `close 900 57` | 시계 새로고침 결과, 이미지로 저장(아이콘만 보일 때), 다시 시도 결과 — 지금 `KH.ui.bubble` 자리 |
| 8 | **따라가기**(툴팁 · 십자선) — 지도 툴팁과 차트 십자선이 포인터를 스프링으로 따라가요(지금 τ 70ms 지수 추종 대체), 옆 타일로 옮길 때 이어서 움직이고 깜박이지 않게 숨김 120ms 지연(지금 규칙) | `follow 900 54`(ζ .9, ≈ 185ms, 90 % 도착 ≈ 115ms — 지금 τ 70ms는 ≈ 160ms); 터치에선 손가락 1:1(스프링 없음) | 지도 타일 툴팁, 종목 차트 · 지수 흐름 선 십자선, 해외 목록 미리보기 카드 |

**보류 · 버림**: Expand card(높이 애니메이션 — 판세 `controls.md` §5-10 금지), Swipe deck · Fan cards(데이터 카드 넘기기 없음), Pull to refresh(시계 누름이 새로고침 — 안드로이드 기본 당겨서 새로고침과도 겹침), Goo · Jelly · Burst류(§2-1).

**확인 방법 제안**: QA는 스프링마다 0 · 25 · 50 · 75 · 100 % 지점 프레임(지금 `?sheet=frames`처럼) + designbookmark식 ×0.25 느린 재생 스위치, 그리고 **실기기 안드로이드**(Emil: 에뮬레이션으로는 남는 hover · 탭 지연 · 고무줄을 재현 못 해요).
